# [ ] Task 002: Scaffold the Svelte + Vite SPA under web/ (pnpm, pinned, audited)

## Description

Create the frontend project under a new `web/` directory using **Svelte 5 + Vite
as a client-only SPA** (not SvelteKit — the lightest single-page setup, no SSR,
no server adapter). The package manager is **pnpm, not npm** — every script,
lockfile, and doc reference in this plan uses pnpm. Scaffold with the pinned
`create-vite` scaffolder and its `svelte` (non-kit) template.

**Pinned tooling (exact versions — pin, do not float).** These are the current
latest at planning time; re-confirm each against its registry at implementation
time (per the version/CVE rule below) and update the pins if a newer patch has
shipped:

- `create-vite` **9.1.2** (scaffolder, run once via `pnpm create`)
- `vite` **8.2.0**
- `svelte` **5.56.8**
- `@sveltejs/vite-plugin-svelte` — pin to the exact latest release compatible
  with Vite 8 + Svelte 5 (resolve the version at implementation time).
- pnpm itself — pin via the `packageManager` field in `package.json`
  (e.g. `"packageManager": "pnpm@<exact>"`) so the toolchain is reproducible.
- Node — pin the runtime via `.nvmrc` and an `engines.node` range in
  `package.json`.

**Pin every dependency to an exact version.** No `^` or `~` ranges. Add a
`web/.npmrc` with `save-exact=true` so future adds stay pinned, and **commit
`web/pnpm-lock.yaml`** — the lockfile is the supply-chain source of truth and CI
must install with `pnpm install --frozen-lockfile`.

**Security is a gate, not an afterthought.** Before this task is considered done,
run `pnpm audit` and resolve or explicitly justify every advisory; review the
dependency tree for supply-chain red flags (unexpected transitive packages,
recently-hijacked names, suspicious install scripts). This mirrors the standing
rule: *always check package versions for CVEs or known supply-chain issues
before pinning them.*

Two serving modes must be supported by the config:

- **Development:** the Vite dev server serves the SPA and **proxies `/api`,
  `/mcp`, and `/healthz` to the serve listener** (default `http://localhost:8082`
  per `config.toml` `server.addr`) so the SPA can call the Go backend without CORS
  or a bearer during local iteration. The proxy target should be overridable
  (e.g. via a Vite env var) rather than hardcoded.
- **Production:** `pnpm build` emits static assets into `web/dist/`, which T003
  embeds via `go:embed`.

Because `web/dist/` is a built artifact and **must not be committed** (it is
generated by the pnpm/Vite step before `go build`), add a `web/.gitignore` that
ignores `dist/` and `node_modules/`. Vite's `base` must be `/` (or relative) so
the built asset URLs resolve when served from the Go binary root.

No application views are built here — only the runnable scaffold and the shell.
The test harness (Vitest + Playwright) is T024; the shared API layer (T005) and
individual views land in later tasks.

## Goal

A `web/` Svelte 5 + Vite client-only SPA scaffold exists, managed with pnpm: all
dependencies pinned to exact versions with a committed `pnpm-lock.yaml`, the
toolchain (pnpm + Node) pinned, `pnpm audit` clean (or every advisory justified),
and a supply-chain review done. It runs under the Vite dev server with an API/MCP
proxy to the serve listener, builds to `web/dist/` with `pnpm build`, and
gitignores `dist/` and `node_modules/`.

## How to Verify

- `web/package.json` declares Svelte 5 + Vite (no SvelteKit dependency), pins
  every dependency to an **exact** version (no `^`/`~`), sets `packageManager`
  to a pinned pnpm and `engines.node`, and defines `dev`/`build` scripts.
- `web/.npmrc` sets `save-exact=true`; `web/pnpm-lock.yaml` exists and is
  committed; `pnpm install --frozen-lockfile` succeeds with no lockfile drift.
- `pnpm audit` reports no unresolved advisories (or each remaining one is
  documented with a justification); the pinned `vite`, `svelte`, and
  `create-vite`/`vite-plugin-svelte` versions were confirmed against their
  registries and checked for known CVEs before pinning.
- `pnpm install` then `pnpm dev` in `web/` starts the dev server and serves the
  shell; requests to `/api/*`, `/mcp`, and `/healthz` proxy to the configured
  serve-listener origin (overridable, default `:8082`).
- `pnpm build` produces `web/dist/` with an `index.html` and hashed assets; Vite
  `base` resolves assets from root.
- `web/.gitignore` ignores `dist/` and `node_modules/`; `git status` shows
  neither as tracked (the lockfile IS tracked).
- No Go files change; `go build ./...` still succeeds unchanged.
