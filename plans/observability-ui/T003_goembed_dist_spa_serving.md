# [ ] Task 003: Embed and serve the SPA with fallback routing

## Description

Wire the built SPA into the Go binary and serve it from the existing serve
listener alongside the current REST + MCP routes. A new Go file (e.g.
`webui.go`) uses `go:embed` to embed `web/dist` and registers a static file
handler plus an SPA fallback on the mux built in `newAPIServer` (`server.go`).

Serving rules:

- Static assets under `web/dist` (JS, CSS, hashed files, `index.html`) are served
  at the site root, on the same listener as `/api/*`, `/mcp`, and `/healthz`.
- **SPA fallback:** any GET that is not an existing static asset and not an
  `/api/`, `/mcp`, or `/healthz` route resolves to `index.html`, so client-side
  routes (e.g. `/runs`, `/logs`) load the app instead of 404ing. The API and MCP
  routes must keep taking precedence over the fallback.

Build coupling (bake in, from the confirmed decision): `web/dist/` is
**gitignored and generated by the Node/Vite build BEFORE `go build`**. `go:embed`
requires the embedded directory to exist at compile time. Document — in a code
comment and by making the failure legible — that building the binary without a
prior `pnpm build` embeds nothing (or fails to compile if `dist/` is absent).
Provide/commit a tiny placeholder (e.g. a `web/dist/.gitkeep` that is itself NOT
ignored, or an embed pattern that tolerates an empty dir) so the package still
compiles in a clean checkout, but make clear that a real UI requires the Vite
build first. Prefer the approach that keeps a bare `go build` compiling while
still embedding the real `dist/` when present.

Do not change auth here — the access model is edge auth with no app-level auth
(T004); `withAuth` is left as-is and is a no-op when `api_key` is unset. The SPA
uses History-API client routing, which is exactly why the fallback route serves
`index.html` for unknown non-`/api`/`/mcp`/`/healthz` paths. This task is static
serving + fallback only.

## Goal

The serve listener serves the embedded SPA from `web/dist` at the root with an
SPA fallback to `index.html`, without shadowing the existing `/api/*`, `/mcp`,
or `/healthz` routes; the package compiles in a clean checkout and embeds the
real assets when `web/dist` has been built. The repo's `Taskfile.yaml` gains a
target that runs `pnpm install` + `pnpm build` in `web/` and then `go build`, so
one command produces the embedded binary in the correct order (dist before embed).

## How to Verify

- The `Taskfile.yaml` build target runs `pnpm build` (in `web/`) then `go build`
  in that order and produces a binary that serves the real SPA.
- After `pnpm build` in `web/`, `go build ./...` succeeds and the running
  serve binary returns the SPA `index.html` at `/` and serves hashed assets.
- A GET to a client-side route path (e.g. `/runs`) returns `index.html`
  (SPA fallback), while `/api/stats`, `/mcp`, and `/healthz` still return their
  existing responses (fallback does not shadow them).
- A clean checkout with no prior Vite build still compiles (`go build ./...`),
  with a comment/placeholder making the build ordering explicit.
- `go fmt`, `go vet` pass.
